# Передача проекта: состояние, что дальше, на что смотреть

Документ для второго разработчика. Актуальное состояние задач всегда в [TASKS.md](../TASKS.md) и [PROGRESS.md](../PROGRESS.md); здесь то, что не видно из кода.

## Что работает сквозным путём (на 2026-11-17)
Вход сотрудников → создание набора → открытие регистрации → QR и ссылка → родитель регистрирует ребёнка (с согласием) → список кандидатов с поиском и фильтром → секундомер испытаний (спринт, челнок, ведение) с сохранением результата. Журнал событий (только добавление) пишется из регистрации, явки и измерений.

В работе или впереди: остальные испытания и исправление результатов, модуль оценки и страница результата, кадры из видео и подключение Claude, отчёт родителю, лендинг. Порядок: [ROADMAP.md](../ROADMAP.md).

## Production: что обязательно
- Переменные `AUTH_URL` (= `APP_URL`) и `AUTH_SECRET`. Без `AUTH_URL` Auth.js отвечает `UntrustedHost` и вход даёт 500 (в dev не проявляется).
- Роль БД для приложения **без прав владельца** таблиц: иначе защиту журнала событий (триггеры против UPDATE и DELETE) можно отключить.
- Не хранить пароль суперпользователя БД в приложении; в `.env.local` разработчика он есть только локально.
- Ограничения неудачных входов и потока заявок хранятся **в памяти процесса**: при нескольких серверах перенести в БД или кэш.
- Видео детей: шифрование на хранении, срок хранения, автоудаление после набора и отправки отчётов (T-045).

## Известные ограничения и долги
- Таблицы Auth.js (аккаунты, сессии) не нужны: используются JWT-сессии.
- Нормативы для перевода тестов в балл 1–5 не заданы (Q-6): нельзя придумывать цифры, ждём источник. Порог «сильного расхождения тренеров» временный (Q-7).
- Работа без связи на поле (очередь событий на устройстве, T-032) не сделана; идентификатор события для повторной отправки уже есть.
- PDF и отправка отчёта родителю (T-051, T-052) не сделаны.
- `login_attempt` в журнал не пишется (у неизвестных адресов нет академии).

## Особенности окружения разработки
- Одна общая команда (типы, линтер, тесты, сборка) не укладывается в лимит 8 минут при запуске из ИИ-агента: запускайте сборку отдельно (до ~70 с).
- Тесты на БД идут параллельно по файлам: создавайте свои данные с уникальными именами и не считайте записи по всей БД. Для очистки журнала в тестах есть `tests/helpers/events.ts` (в приложении журнал не очищается).
- В `psql` на Windows задайте `PGCLIENTENCODING=UTF8` для русских строк.
- Встроенная панель браузера в приложении Claude не вызывает `requestAnimationFrame`: потоковые страницы с `<Suspense>` остаются на заглушке, пока вручную не вызвать `window.$RV(window.$RB)`; в обычном браузере так не бывает. Гидратация в dev-режиме наступает через ~10 секунд после первой компиляции.
