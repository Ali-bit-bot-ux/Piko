# Журнал событий (решение по Q-2)

Статус: принято владельцем (D-015).

## Решение
Источник истины — **серверный append-only журнал событий** (аудит), а не логи мобильного приложения. Мобильный офлайн-кэш синхронизируется с сервером. Исправление создаёт новое событие, а не перезаписывает старое.

## События
| Событие | Инициатор | Зачем |
|---|---|---|
| registration_created | родитель | заявка и согласия |
| consent_granted | родитель | доказательство согласия на обработку данных |
| tryout_published | академия | история публикации набора |
| participant_checked_in | тренер | явка |
| measurement_recorded | тренер | время, попытки, результат |
| evaluation_scored | тренер | экспертная оценка по критерию |
| measurement_corrected | тренер | исправление с причиной |
| evaluation_reopened | директор | спорная оценка |
| decision_changed | директор | смена статуса кандидата |
| report_sent | система | факт отправки родителю |
| report_opened | родитель | доставка/просмотр |
| login_attempt | пользователь | безопасность |

## Поля события
`event_id` (UUID) · `event_type` · `actor_id` · `actor_role` (parent/coach/director/admin) · `academy_id`, `tryout_id`, `participant_id` · `occurred_at_device` · `occurred_at_server` · `payload_hash` · `previous_event_id` (цепочка по объекту) · `source` (mobile_offline | mobile_online | web | system) · `ip_hash`, `device_id_hash` (обезличенно).

## Правила целостности
- Только добавление: без UPDATE и DELETE (на уровне БД запретить права).
- Для измерения хранится цепочка: исходное значение → исправления, причина, автор, время.
- Родитель видит результат, но не фамилию тренера.
- Хранение логов минимум 12 месяцев; согласия и спорные решения по политике хранения ПД.
- Минимизация данных: собирать только нужное для набора и отчёта.

## Для реализации
- Таблица `event` в БД, запись через единый сервис `src/server/events/` (задача T-008). Состояние (Score, Measurement) строится из событий или синхронизируется с ними, это решить в T-008.
- Офлайн-ввод тренера (T-032): события с `occurred_at_device` ставятся в очередь на устройстве и отправляются при связи. Идемпотентность по `event_id`.

## Журнал и удаление данных: решено (Q-9, D-020)
Видеозаписи удаляются после завершения набора и отправки отчётов родителям. Журнал хранит только псевдонимные ID, имена и контакты удаляются отдельно по запросу.

Исходная постановка:
Неизменяемый журнал vs право родителя удалить данные ребёнка (AGENTS.md, правило 4). Предлагаю: в событиях хранить только псевдонимные ID (`participant_id`) и хеши; имя и контакты лежат отдельно в таблице Candidate и удаляются по запросу, журнал остаётся обезличенным. Подтвердить с юристом (T-064).
